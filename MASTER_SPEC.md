### 0.1 Definitive product scope

A local-first, channel-aware, reusable-asset **2D cutout animation video factory**: Channel → Project → external Idea/Script/Shot Plan → Asset Resolver → G-Labs visual asset production → local Native Rig → external Animation Director JSON → motion compile on reusable rigs → Spine/PixiJS rendered shots → Kokoro/ElevenLabs voice/timing reconciliation → FFmpeg H.264/AAC MP4 + QC report.

MVP: 1–2 humanoid actors per shot, front/three-quarter-or-side single approved view per rig; 1–3 props per shot with **one actively gripped prop per hand**, one background per shot, 24 FPS, 1280×720, 30–60s full acceptance film, 30 shots maximum. Action inventory: `idle`, `walk_to`, `look_at`, `reach_for`, `grab`, `carry_to`, `place_at`, `point_at`, `react`. Actors can walk and look simultaneously, and can walk while holding a prop. Support only a **single-floor-level** scene; no real 3D depth, jumps, fighting, cloth physics, 360° turns or phoneme lip-sync in MVP. Preserve ordinary sprite-expression swapping.

## 3. Persistence, identity, lineage and state machine

### 3.1 IDs and immutable bytes

IDs are backend-generated, never LLM-invented except echoed reserved IDs. Use lowercase `uuid.uuid4().hex` suffixed by prefix: `chn_`, `prj_`, `art_`, `ast_`, `av_`, `rig_`, `rv_`, `mot_`, `mv_`, `op_`, `job_`, `res_`; regex `^(chn|prj|art|ast|av|rig|rv|mot|mv|op|job|res)_[0-9a-f]{32}$`. Shot/actor semantic IDs are local IDs: `shot_[a-z0-9_]+`, `actor_[a-z0-9_]+`; `semantic_key` is `^[a-z][a-z0-9_]{1,63}$`. IDs are immutable.

Serialize canonical JSON with Python `json.dumps(sort_keys=True, separators=(',', ':'), ensure_ascii=False, allow_nan=False)` encoded UTF-8; `sha256:` + lowercase digest. Artifacts stored under `{ARTIFACT_ROOT}/{project_id}/{artifact_id}/{sha256hex}.{ext}`; Asset versions under `{ARTIFACT_ROOT}/library/{channel_id}/{asset_id}/{asset_version_id}/...`. Write to unique same-volume temp path; validate bytes; atomic rename; transactionally commit metadata/current pointer. On losing CAS conflict, remove only temp/attempt-owned paths, never delete historical objects. Store original provenance, prompt hash, G-Labs task ID, stage input hash, generation params, source hashes and approval actor/time. No in-place edits to approved versions.

### 3.3 Project stage authority / invalidation

A consumer must validate exact current head artifact ID, content hash, approval state and dependency hashes; historical artifacts never get silently substituted. Stage heads may be updated only with transactional compare-and-set on old head SHA/ID. Invalidation **marks downstream heads stale**, does not delete historical bytes. `stale` is a computed readiness state based on dependency fingerprints (head status stored as `approved`, `draft`, `rejected`).

| Changed approved input | Invalidate/rebuild |
|---|---|
| Channel DNA visual identity | `asset_requirements`, `asset_resolution`, generated asset eligibility, rig compatibility where visual replaced, director, motion, final |
| Channel DNA narration/style guidance | external authoring prompts and downstream if script changed; voice identity/timing if voice changed |
| Topic selection | script, shot plan, resolver, director, motion, voice, final |
| Script | shot plan, resolver, director, motion, voice, final |
| Shot Plan | resolver, animation plan, compiled film, shot previews, final timeline/MP4; **existing catalog assets remain approved** |
| Approved asset/rig version binding | resolver, director, motion, affected shots, final; other shots unchanged |
| Animation Plan | compiled film, motion previews, final; no G-Labs task invalidation |
| Motion template version | compiled shots that reference template revision, final |
| Voice audio or alignment | timing reconciliation and final render only; no script/rig regeneration |

The **asset registry is channel-scoped**, persistent across projects. Projects pin **exact asset_version_id and rig_version_id**. A newer approved version does NOT migrate old projects unless the user explicitly rebinds it.

### 3.4 Durable operation rules

Allowed operation states `queued`,`running`,`completed`,`failed`,`cancelled`,`ambiguous_submission`; tasks `pending`,`submitting`,`submitted`,`running`,`completed`,`failed`,`cancelled`,`ambiguous`. Worker acquires DB lease with owner token/fencing; retries are recorded as new attempts, not blind replay of requests that may incur cost. A G-Labs POST failure after submission intent but before definitive response sets `ambiguous_submission` and **must not auto-post again**. GET does not advance execution. Worker reconciles at most one poll per due task per turn and exponential delays capped at 30s. `cancel` blocks future submissions and requests provider stop only for known task IDs. FFmpeg/spine operations are idempotent by exact input hash, use attempt-specific directories, and cannot publish from stale worker tokens. On restart, recover queued/running operations from DB leases, never from memory.

## 4. Contract registry and JSON validity policy

All companion files in `contracts/schemas/` are JSON Schema Draft 2020-12; enforce `additionalProperties:false` for every object (unless expressly freeform). For every import: parse with duplicate-key rejection; JSON Schema validation; referenced IDs check; source hash and reservation check; domain semantic validation; resource/capability validation; only then publish. NaN/Inf, bool-as-int, unsupported enum and unknown fields are rejected. Schema filenames and required fields are **normative**. Do not make up additional schema fields. Validation error response:

```json
{"error":{"code":"ANIMATION_ACTION_UNSUPPORTED","message":"Action is not supported by rig capabilities.","retryable":false,"details":{"path":"$.shots[0].actions[2]","action_id":"act_grab_1","rig_version_id":"rv_..."}}}
```

Actual IDs in examples are illustrative, but runtime IDs must match §3.1. HTTP status: malformed/semantic payload 422; stale sources, conflict or state 409; missing IDs 404; body/resource limit 413; unavailable required local dependencies 503; provider network failures 502/504. UI displays actionable field path/code. `validate` endpoints have **zero DB/file publication side effects**; import endpoints independently revalidate all constraints.

### 4.2 Semantic rules that JSON Schema alone cannot express

1. `script.sections[*].section_id` unique; `narration_text` nonempty; `full_narration` must equal section text joined by **two newline characters** in canonical section order; no automatic rewrite of dialogue.
2. `shot_plan.shots[*].shot_id` unique, contiguous `order=1..N`, planned durations 1–30 sec, total target 30–60 sec for **acceptance fixture only** (regular production permits any duration up to 30×30sec). Script section refs must exist. The exact narration character range for each shot partitions relevant section text without overlap/gaps and has exact quote equality.
3. `asset_requirements` created **deterministically** from approved Shot Plan plus Channel DNA: one requirement per unique `(kind,semantic_key,view)` and static world asset variant; sorted `(kind,semantic_key,view)`. `asset_resolution.requirement_id`s match exactly and only `approved` versions are assignable.
4. `animation_plan` **must echo** the approved `shot_plan_artifact_id`, `asset_resolution_artifact_id`, `source_hash` and reserved `artifact_id`; identical shot IDs and durations (integer planned frame counts) unless a user has explicitly revised Shot Plan. No extra characters/props/assets. Each action must refer to a declared actor and approved rig capabilities. No last-minute content from model.

## 8. Stage 4 — Native Auto-Rig (P3/P4); no Genielabs dependency

### 8.1 Output artifacts

Rig Workshop stores: `character_reference.png`, `parts_atlas.png`, `parts_manifest.json`, `layout.json`, `joints.json`, per-part transparent PNGs, `skeleton.json`, `skeleton.atlas`, `skeleton.png`, `rig_profile.json`, `rig_manifest.json`, `rig_qc.json`. Publish a **single immutable rig version** only when mandatory files exist and validations pass.

### 8.2 Parts segmentation algorithm — implement `segmentation.py`

- Input RGBA atlas; reject no-alpha until user approves explicit chroma-removal action. Foreground `alpha>=16` (8-bit); run 8-connected-component labelling on binary mask, min area `max(64, ceil(total_pixels*0.00005))`; discarded components remain in diagnostic log.
- For an approved **single-component-per-part** atlas, require exactly 14 kept components. Each component gets a UUID-local part ID and `bbox`, area, mean alpha. Crop with 8-pixel transparent padding; **mask non-component pixels to transparent** (no white rectangle contamination). Output sorted components by `(bbox.top, bbox.left, area DESC)`; this is only deterministic part indexing, not semantic recognition.
- If >14: user can merge selected component IDs; if <14: user must draw split mask(s) in workshop or regenerate atlas. Splits preserve original pixels and partition masks exactly; no pixel belongs to two parts; custom merging is explicit. Export accepted `parts_manifest` mapping 14 semantic names to exact component sets/masks. Don't call external segmentation services.
- Transparent anti-alias edges: preserve original RGBA where mask true; 2px neighborhood expansion with alpha-only edge feathering limited to existing foreground support; no RGB hallucination. Persist mask SHA and source image SHA.

### 8.3 Part placement — `positioning.py`

- Input assembled reference image, 14 approved part PNGs, estimated initial bboxes, semantic map. CV pipeline: alpha-masked SIFT descriptors on part/reference; Lowe ratio `0.75`; partial affine RANSAC reprojection threshold `3px`; require >=4 inliers and inlier ratio >=0.60; constrain positive uniform scale `[0.5,2]`, abs rotation `<=45°` relative to atlas orientation. Output transform and confidence.
- If SIFT cannot meet constraints, use alpha-mask normalized template matching over scales `0.75..1.25 step .05`, rotations `-30..30 step 5°`; require score >=0.85 and foreground overlap >=0.70. If fallback fails, mark `needs_manual_placement`, do not synthesize a transform.
- Compute draw-order proposal from pairwise overlap/color consistency with reference. Cycles/ties → `needs_manual_draw_order`; final `z_index` must be explicit integer unique per part. Display assembled overlay and discrepancy heatmap in Workshop. Confirm `layout` with user approval before building rig.
- **Caveat:** generated separated parts can have artwork missing from the assembled reference, so image feature matching may inherently fail. Manual transform is the specified fallback, not an algorithmic bug to hide.

### 8.4 Anatomy, pivots, and geometry — `anatomy.py`

- Required 14 semantic regions (as listed §7.2). Map exactly one part per role. Required joints: `pelvis`, `neck`, `left_shoulder`, `left_elbow`, `left_wrist`, `left_hip`, `left_knee`, `left_ankle`, `right_shoulder`, `right_elbow`, `right_wrist`, `right_hip`, `right_knee`, `right_ankle`. Joints specified in **reference image pixel coordinates** x-right/y-down, finite within canvas. Automatic proposal may use fixed relative positions from placed region geometry but carries `verified=false`; MVP **requires manual approval** of all 14 joint coordinates. No claim of one-click anatomy detection.
- Validate segment lengths >5 px, arm and leg chains, and warn on near-singular fully extended rest poses (use explicit bend sign to solve ambiguity), left/right symmetry only as warning, attachment connections under overlap with at least 2 px hidden texture where possible. Reject missing parent, bone cycle, duplicate semantic role, out-of-canvas joints, NaN/Inf, zero length. Report joint quality flags.
- Convert reference pixels to world-like rig local `x'=x - pelvis.x`, `y'=pelvis.y - y` (units: rig pixels); **do not flip again in the browser**. Construct bone rest matrices from actual joint vectors, not a forced neutral +X arm. For parent at joint `Jp`, child at `Jc`, desired world heading `θ=atan2(Jc.y-Jp.y,Jc.x-Jp.x)`; child local translation `R(-θparent)*(Jc-Jp)`; local rest rotation `θchild-θparent`. Final runtime pose matrix reuses these bone transforms. Preserve connected joint world positions within 0.25 px after load.
- Root positioned at pelvis, body bones attach relative to semantic joints; slot image center is transformed into its bone-local rest coordinate by inverse bone rest matrix. Do not place images at bone center unless actual layout demands it.

### 8.5 Native Spine 4.2 builder — `spine_builder.py`

Output top-level `{skeleton,bones,slots,skins,animations}`; skeleton metadata includes `spine:"4.2.0"` and actual canvas extents; parent-before-child bone order; deterministic names `root`, `pelvis`, `torso`, `head`, `left_upper_arm`, `left_forearm`, `left_hand`, `right_upper_arm`, `right_forearm`, `right_hand`, `left_thigh`, `left_shin`, `left_foot`, `right_thigh`, `right_shin`, `right_foot`. `head` attaches to `torso`; upper arms to `torso`; thighs to `pelvis`. `torso` to `pelvis`; lower limbs to upper; foot to shin. Names match `RigProfile`. Slots deterministic back-to-front order from approved z-index, with `attachment` key exactly matching texture region name. `skins` is Spine 4.2 array, default skin has all 14 slot attachments. MVP images use region attachments, no weighted mesh, no FFD, and `animations:{}` is valid: local motion engine drives bones per frame. If optional idle/test animations are authored, obey Spine 4.2 `rotate.value`, not `angle`; translate bezier contains 8 values, and curves belong to segment's **starting keyframe**.

**Expression-swap rigging contract:** `expression_sheet` from G-Labs is separate from the 14 mandatory cutout parts. After human approval, crop each supported face expression to a transparent PNG with its own mask and save an exact `neutral`/`happy`/`surprised`/`angry` label. Add an optional `face` slot parented to `head`, with four region attachments sharing one approved local eye/mouth anchor; the head/face sheet remains spatially aligned on all poses. A missing expression attachment must be absent from `RigProfile.expressions` and blocks any matching `react` action. For the P11 movies, both real approved rigs require `neutral`, `happy`, and `surprised`. The actual attachment atlas packing includes these optional regions in the same single page, but the required `parts_manifest` continues to contain exactly 14 anatomical regions. The user must inspect each expression pose before rig approval.

`atlas_builder.py`: deterministic 2D pack by `(height DESC, semantic name ASC)`, one page max 2048 px, 4px clear packing margin plus 2px extruded RGB edge padding to prevent linear sampling seams; never add visible alpha outside region. Atlas `size`, `format: RGBA8888`, `filter: Linear,Linear`, `repeat: none`, per-region `xy`,`size`,`orig`,`offset`,`index`; output PNG+atlas, validate by official Spine/Pixi loader in browser. If cannot fit one page raise `RIG_ATLAS_CAPACITY`; never silently downscale character parts.

### 8.6 RigProfile and QA — `rig_profile.v1` schema

Store source JSON/PNG SHA, bone role map, rest matrices (one affine transform `[a,b,c,d,tx,ty]` per required bone; `x_world=a*x_local+c*y_local+tx`, `y_world=b*x_local+d*y_local+ty`),, actor pivot (`pelvis`), world scale (`pixels_per_meter`), limb chains with numeric lengths, hand sockets in each hand's bone-local pixels, supported approved actions, named faces/expressions (MVP allowed `neutral`,`surprised`,`angry`,`happy` only when corresponding attachment exists). `supported_actions` mechanically derived from required bones/foot contacts/sockets, not a free-text claim. `walk_to` only after **live preview foot stability approval**; hand interactions require their hand socket; `react` requires a valid expression. Rig QC checks rest skeleton render, 14 visible required regions, 2 arm IK reach targets, 2 leg IK reach targets, random seek determinism and sampling. Mark `rig_status=needs_review` until user chooses Approve after preview; quality warnings never auto-pass approval.

## 10. Stage 6 — Motion Planner, WorldState, animation runtime (P5–P7)

### 10.1 Deterministic evaluation model

Compiler inputs (all pinned): `shot_plan`, `asset_resolution`, rig profiles + Spine files, `animation_plan`, `motion_library_version`, motion profile settings. Compiler output `compiled_film.v1` plus one per-shot file. For each shot, simulate frames `0..N-1` using pure function `state_at(frame)` on a **compiled snapshot**, not incremental browser frame state. On Python compile, build complete frame transforms and world prop ownership; browser only consumes frame state, applies transforms and renders. Hash inputs and output, no wall time/random state.

**Order on each frame:** (1) current persistent WorldState; (2) evaluate locomotion/root; (3) evaluate base procedural gait/idle; (4) apply gaze; (5) solve arm reach/carry/point with IK and track priorities; (6) solve leg IK + foot locks; (7) apply expression; (8) execute interaction boundary events; (9) compute prop transforms from owning grip; (10) compose camera and emit actor/prop/bone transform snapshot; (11) validate finite/reach/contact constraints. Events use exact integer frames, and `frame_at(n)` must equal regardless of seek order.

### 10.2 Coordinates, camera and transform chain

Authoring world unit **meters**, x right, y up. Rig part pixels y flipped once during rig build. Renderer output pixels x right, y down. Default camera `center_world={x:0,y:1.5}`, `zoom=1`, `pixels_per_meter=100` (chosen so a 3m vertical region is visible in 720p). World to screen at resolution W,H:

```
screen_x = W/2 + (world_x - camera.center_world.x) * 100 * zoom
screen_y = H/2 - (world_y - camera.center_world.y) * 100 * zoom
```

Bone local positions use rig pixels. Actor rig scaling = `world_height_meters / (rest_skeleton_height_pixels/100)` normalized via manifest; default humanoid world height 1.7m. Apply model transform `world_translation + uniform_scale × (Spine-local coordinates converted from rig px to meters)`. Prop PNG has metadata world_w/h and anchor center; prop socket is bone-local point transformed by actual world bone matrix. Camera does not affect physics/contact; apply only after world coordinates solved. Root actor y=0 floor. Never mix screen px into world contact tests. Rig rest matrices and inverse are evaluated in double precision; serialized values rounded to six decimals **only at final frame output**.

### 10.3 IK and reachable targets

Implement analytic two-bone IK in `ik.py`. For upper length `L1`, lower `L2`, target vector `d=(target-joint_root)`, distance `r=norm(d)`; reachable iff `abs(L1-L2)+epsilon <= r <= L1+L2-epsilon`, `epsilon=0.002m` after scaling. Clamp only within numerical epsilon; otherwise error `MOTION_TARGET_UNREACHABLE`. Elbow interior angle from cosine rule `cosγ=(L1²+L2²-r²)/(2L1L2)`; shoulder adjustment from `acos((L1²+r²-L2²)/(2L1r))`; select fixed bend direction `left:+1/right:-1` defined in RigProfile and retained across frames. Require smooth elbow side continuity; if solver flips sign discontinuously fail `MOTION_IK_FLIP`. Constraints target error <= 0.005m; hand contact error <=0.003m. Hip/knee/ankle chains use same IK with explicit knee bend direction.

### 10.4 Locomotion and foot locking

MVP root path **straight-line** from starting world point to target. Walk starts/ends with smoothstep acceleration/deceleration over first/last min(6, floor(duration/4)) frames, constant midsection approximated by normalized piecewise integral. Reject requested speed if implied distance vs duration differs by >20%; do not secretly change duration or target. Walk cycle is procedural 12-frame cadence by default, parameterized by stride length `0.32m`, hip bob amplitude `0.02m` and arm swing ±12° on unoccupied arms; choose stride count `max(1,round(distance/0.32))`, re-time phase to land exact final position. During stance foot remains fixed world position using IK; during swing foot moves in x between contacts and `y=0.06*sin(pi*t)` meters. On final frame both feet return to y=0. Detect sliding >0.01m during stance; reject if legs cannot solve. No walk on incline/stairs or nonzero floor.

### 10.5 Blending and acting templates

Track priority lower to higher: base idle/walk → gaze → upper-body action → expression → hand/prop contact. Bone masks: locomotion owns root/pelvis/legs, default arm swing; upper-body owns chosen arm and optional torso weight; gaze owns head; expression swaps face attachment. When upper-body uses one arm, its swing weight becomes zero while the other arm continues. Transition over `min(4, action_duration//4)` frames using smoothstep `t*t*(3-2*t)`; no interpolation across discrete grab/release events. Idle breathing: torso translate Y by `0.005m*sin(2πt/1.6s)` and head small ±1.2° sin cycle. React expression switches at start and remains until replaced or end Shot; no automatic head bob invented. Optional manually approved `anticipation` keyframes are out of MVP unless added as a versioned motion template with tests.

### 10.6 Ownership/interaction and shot continuity

Global `WorldState` keyed `actor_id`, `prop_id`, `location_key`, fields for world transform, rig version, face, hand ownership. Prop FSM: `free → grabbed → held → released → free`. At `grab.start_frame`, assert prop center vs evaluated grip world coordinate <=0.01m and mark `owner=(actor_id,hand)`. While held, `T_prop_world = T_hand_bone_world × T_socket_local × T_object_grip_inverse`; preserve orientation. At `place_at.end_frame-1`, prop reaches target with error <=0.005m and ownership releases; next frame free with exact same transform. Prop cannot teleport between shots in same `location_key` without an explicit narrative `cut` and independently authored placement; **even `cut` does not allow silent ownership change**. Validate actor identity, view/rig binding, world-space prop position and ownership across shot boundaries. Each shot has starting/ending snapshots; next shot defaults to exact previous state except for explicitly declared camera/background or legal `cut` pose changes.

**Do not merge two distinct `location_key`s solely because their screen coords happen to match.** If a prop crosses locations, MVP rejects with `CONTINUITY_LOCATION_TRANSFER_UNSUPPORTED`. If actor not visible in a shot its world state persists unchanged.

### 10.7 Compiler resource limits and errors

Max 30 shots; at most 720 frames per shot; at most 2 actors/3 props simultaneously; max 50 actions per shot; max compiled JSON per shot 64 MiB, else `COMPILE_SIZE_LIMIT`. Recheck every referenced SHA/file before compile. Reject NaN, missing socket, duplicate action event, nonmonotonic frame indices, track overlap, unsupported pose, invalid hierarchy, rig/frame mismatch. Run `compile_film` twice from same frozen inputs; JSON canonical hash must match exactly.

### 10.8 Spine/Pixi runtime contract

`runtime/spine` loads approved `skeleton.json + .atlas + .png` from project-scoped read-only URLs. Use official `@esotericsoftware/spine-pixi-v8` 4.2.x, PixiJS >=8.16, `Spine.from({skeleton,atlas,autoUpdate:false})`; per frame **reset skeleton to setup pose**, then apply compiled bone-local `x,y,rotation,scale` transforms and face attachment, update world transforms, place prop sprites via world/scene transform, apply camera, `app.render()` exactly once. Disable ticker and animation-state wall-clock advances. Render via Playwright Chromium `seek(frame)` / canvas PNG screenshot; screenshots produced into temp attempt-specific directory; never share global fixture folders or ephemeral ports. WebGL/ANGLE software fallback on headless Windows/Linux. `window.__RENDER_READY__` and `window.__RENDER_FRAME__(index)` for driver; return `{frame,shot_id,actor_count,prop_count,sha256?}`; **Python/Node checks** SHA on resulting bytes, JS does not need crypto dependency.

## 11. Stage 7 — Shot Rendering, Voice, exact timing, MP4 (P8–P10)

### 11.1 Render stages and reusability

Render **silent** shot clips or PNG frame sequences from `compiled_film`; cache each `rendered_shot` by `{compiled_shot_hash,rig_version_hashes,renderer_version,resolution,fps}`. Output frame count exact; backgrounds must cover whole frame; overlays face/props; no title overlays unless authored. Preview may run at 640×360 but final must be 1280×720, both deterministic at respective resolution. Separate artifacts for preview/final.

### 11.2 Voice provider reuse

Port coherent YTB Kokoro/ElevenLabs voice adapters in P8 with their tests. Canonical output format **mono PCM16 48000Hz** (aligns YTB). Kokoro model/voice filenames canonical: `kokoro-v1.0.onnx`, `voices-v1.0.bin`; setup calibrates exact runtime and refuses mismatched identity. ElevenLabs forced alignment (if credentials present) is the authoritative word-timing source; **do not use YTB disabled/fallback pseudo alignment as genuine word timing**. If alignment service unavailable, allow verified section/shot **start-end timing only**, explicitly mark `word_alignment_status=unavailable`; subtitles use shot text without word highlighting. Voice selection from channel profile; support Kokoro local and ElevenLabs generation; provider-disabled mode accepts a user-imported validated WAV. No real speech provider in CI; synthetic WAV only marks technical pipeline tests.

### 11.3 Voice windows and final reconciliation algorithm

Each ShotPlan shot declares an exact narration text and `duration_frames`. Stage 7 voice produces one WAV per shot, duration in samples `S`. Narration cue default at `start_frame=0`; user may set `start_frame` within shot before generating voice. `available_samples=(duration_frames-start_frame)*2000`. If `S<=available_samples`, pad silence **at end** (never stretch speech). If overflow `Δ=S-available_samples>0`, do **not** truncate, compress speech, silently overlap following shot, or violate physics events. Reconciliation first extends shot by `ceil(Δ/2000)` frames up to **max 48 added frames** and max 30 seconds/shot; only legal action state after the last timeline event may be held, with loop-safe idle/head micro-motion. If no legal hold (prop airborne, pending grab, walking unfinished, required fixed cut) or extension exceeds bounds, mark `VOICE_WINDOW_OVERFLOW`, user must edit Shot Plan/Voice or regenerate narration. Extended shot causes absolute later shot start shifts; persists `final_timeline.v1` distinct from frozen `shot_plan` and `compiled_film`. **Rerender only extended shots** with new hold frames. Do not resample one frame into multiple frames or change event frame indices.

At 24FPS, exactly 2000 48kHz audio samples/frame. Concatenate per-shot canonical PCM into a film-length buffer, pad silence to each final shot window, reject overlap/out-of-bounds. Subtitle SRT/VTT generated from narration cues and alignment if available; if no alignment, cue spans entire shot narration WAV duration. SRT times quantized from exact sample count, not assumptions about words.

### 11.4 FFmpeg final encoding and validation

Use Python `subprocess` with shell=False via extracted YTB process helpers, max resource limits, worker cancellation and progress parser. Recommended deterministic command shape (actual paths passed as separate args, not string concatenation):

```
ffmpeg -y -framerate 24 -start_number 0 -i shot_%06d.png \
  -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p -r 24 \
  -an -movflags +faststart shot.mp4
```

Concatenate per-shot H.264 frames without using variable FPS; safest default is **single continuous frame sequence encoding** for MVP (avoids codec/GOP concat mismatches); shot files are cacheable and can be decoded to sequences, but final pack must verify frame count. Mux 48k WAV into AAC 192k, `-shortest` only when exact durations already verified; otherwise explicit `-t` computed from final frames. Final `ffprobe` checks 1280×720, r_frame_rate=24/1, avg_frame_rate=24/1, read_frames=`total_frames`, H.264 yuv420p, AAC stereo/mono acceptable after encoder, video duration error <=1/24 sec and no unexpected silent file. Store ffmpeg logs bounded/redacted. MP4 SHA and QC report are immutable artifacts, published atomically when all gates pass.

### 11.5 Visual + temporal QC

Machine gates: all frames nonblank, no missing PNG, actor always renders, no detached prop (>0.003m), no unresolved skeleton role, max foot sliding 0.01m during stance, no actor/prop teleport without explicit cut, output matches frame count and audio length. Replay sample at first/middle/last frames of **every shot** and arbitrary seek order `[last,first,mid]` compare hashes inside same runtime/environment. Quality gate requires user review of 4–8 key screenshots per shot and real generated asset continuity; non-deterministic visual aesthetics cannot be promised by tests alone. For real test, use one actual G-Labs character plus manually corrected rig, not test-only synthetic shapes.

## C. Deterministic gait easing and runtime sampling formulas

To avoid implementation-dependent interpretations of “smooth start/stop”, calculate locomotion progress over `N` frames exactly:

```
segments = N - 1
ramp = min(6, max(1, floor(N/4)))
for i in 0..segments-1:
    weight[i] = min(1.0, (i+1)/ramp, (segments-i)/ramp)
normalizer = sum(weight)
progress(0)=0
progress(f)=sum(weight[0:f])/normalizer  for 1<=f<N
position(f)=start + progress(f)*(target-start)
```

`progress(N-1)` must equal 1 to machine tolerance 1e-12. `idle` uses absolute frame time `t=frame/24`, not accumulated `deltaTime`, so seeking the same frame always yields the same motion. Loops use phase `2π*(frame mod period_frames)/period_frames`, not wall-clock. Camera interpolation uses `smoothstep` between exact keyframe indices (never use ticker). Serialize six decimal places at frame snapshot boundary only. All axes and speeds are as §10.
