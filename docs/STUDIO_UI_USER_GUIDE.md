# AI 2D Animation Studio — Local cockpit manual testing (Windows)

## 1. First-time setup

On Windows install **Python 3.12**, **Node.js 22**, and **FFmpeg + ffprobe** on PATH. From the `feat/p0-p1-foundation` branch of the **AI-2D-Animation-Studio** repository, double-click **`setup_studio.bat`**. It installs backend/React and Spine/Playwright dependencies, builds the frontend and downloads two **pinned** open-source Genielabs builder scripts to `vendor/genielabs/scripts` if not present. These are fetched from the Genielabs GitHub commit `702b71689cac826efee942ee4564fef9560d6ef8`; they do **not** call Gemini or G-Labs. If you want to review third-party code before using it, inspect those source files first.

For daily use, run **`start_studio.bat`**, which starts the local backend and serves the built UI at **http://127.0.0.1:8000**.

No secrets/API keys belong in React or the repository. The web server binds only to `127.0.0.1` by default.

## 2. Full no-cost demonstration

1. Open **Projects** → enter name → select **Coffee Cup Save** or **The Lost Key** → Create.
2. Open **Director Studio** to inspect five shots and edit camera angle, narration, and the `film.v2`/`catalog`/`motions` JSON. Save/validation is explicit.
3. Open **Asset Library** → click **Prepare demo assets (offline)**. This generates two five-part synthetic Genielabs Spine rigs, story-specific background PNGs, prop PNG and five two-second synthetic tone WAVs **inside this project**. Real spoken narration is NOT generated. The demo button overwrites assets having the template demo filenames; do not use it after importing custom art you wish to preserve.
4. Select **Render & Review** → Recheck. Required assets, dimensions, rig geometry and film continuity are validated. Once ready, click **Start render**. This runs existing `film.v2` → Spine/PixiJS → PNG → FFmpeg H.264+AAC through the local backend, without G-Labs or Kokoro.
5. On completion, review the MP4 embedded in the Render tab and download it. Because the demo has synthetic artwork and tone WAVs it proves software integration only — it is NOT a publishable animated movie.

Rendering requires Chromium installed with Playwright and FFmpeg. One render may run at a time because the current renderer still stages resources in a shared `runtime/fixtures` folder.

## 3. Import your own assets

The Asset Library lists every required file and lets you upload to the exact path declared in `AssetCatalog`:

- A **Spine rig** comprises `skeleton.json`, `skeleton.atlas`, `skeleton.png`, and `rig_profile.json` for each rig ID. A single flat character illustration cannot substitute for an authored/validated rig. For AI assets, first run the separate Genielabs workflow with explicit semantic part labels and joint anchors.
- **Background** and **prop** files may be PNG, JPEG or WebP; the backend decodes them and writes a normalized PNG under the target catalog filename. Background resolution MUST match the film output dimensions.
- **Voice** per shot must be a PCM16 mono 24,000 Hz WAV. This is a WAV import pipeline, not a Kokoro TTS connection. It checks narration duration against its shot start and end.
- You can edit imported JSON and motions manually, but the compiler rejects unknown asset IDs, mismatched lengths, unreachable arm positions, and discontinuous actors/props across ordinary cuts.

For images generated by external AI, use the same import path. **G-Labs authenticated Windows webhook end-to-end remains unverified**. Do not mistake the demo bootstrap for an authenticated real asset pipeline.

## 4. Reuse and limitations

Projects save JSON, assets, renders and intermediate frames under `workspace/projects/<project-id>` by default. The backend returns render job status while running; the job registry is currently **in-memory** (lost after backend restart), although successful MP4 files stay on disk. Project data is local and never uploaded automatically.

The interface follows the **cockpit navigation and stage-based review design** of your `plthien/ytb-ai-studio` frontend without copying its YouTube-only business logic.

**Quality limitations:** There is currently no universal full-body auto-rig, leg locomotion, expressive face/lip-sync, rigid-body physics, or AI art-quality scoring. The basic motion primitives and 5-part synthetic examples remain simple. Actual G-Labs and Kokoro live provider workflows, persistent background queue, simultaneous project rendering, and a full interactive keyframe animation editor are not yet production-tested.

## 5. Troubleshooting

- UI doesn't open: check `python -m studio` console and `frontend/dist`; rerun `setup_studio.bat`.
- `Prepare demo assets` fails: ensure both `vendor/genielabs/scripts/build_spine_json.py` and `make_atlas.py` exist; rerun setup.
- `Ready` not displayed: open Render & Review for the exact missing file names, bad PCM format or bone geometry mismatch.
- Renderer fails: install Chromium (`cd runtime && npx playwright install chromium`), and check `ffmpeg -version`, `ffprobe -version`.
- Manual AI import: film/motion JSON should use the `film.v2` schemas; syntax-valid JSON may still fail domain validation, which should show HTTP 422 details in the UI.
