# P4 — Native Auto-Rig and Rig Workshop
**Prerequisite:** approved P3 plus **approved real or CI-fixture** character reference and same-character parts atlas. **Owning skill:** `native-auto-rig`. **Schemas:** `parts_manifest`, `rig_layout`, `rig_joints`, `rig_profile`, `rig_manifest`, `qc_report`.

## Work orders, numerical authority and files

**P4.01 Segmentation.** Implement `app/modules/rigging/segmentation.py: segment_parts(reference_png,atlas_png,alpha_threshold=8)->PartsProposal` using PIL+OpenCV (`opencv-python-headless` pinned, numpy pinned). Require decoded RGBA; binary alpha >=8, 8-connected components, nonzero area, reject overlapping expected roles, anti-aliased edges retained in extracted 4-channel PNG. Components sorted by min(y,x), then area DESC for stable indexing; 14 semantic roles must be reviewed and unique. Manual segmentation editor may split/merge masks but each revision is new `parts_manifest`; source atlas and reference IDs/SHA MUST be distinct and pinned, no guessing disconnected limb mapping.

**P4.02 Positioning.** `positioning.py: propose_layout(reference_rgb,part_masks,semantic_map)->RigLayoutProposal`. Initial feature align via SIFT + ratio test 0.75 + RANSAC similarity transform (min >=4 inlier pairs, reprojection threshold 3 px, scale positive). Fallback mask template placement is a **proposal only**; confidence <0.80 requires human manual placement. A mask with no reliable registration blocks approval until explicit edit. Store positions x,y px, positive scale, rotation degrees, z-index and method, stable byte-level output.

**P4.03 Anatomy.** `anatomy.py: build_joint_proposal(rig_layout,manual_anchors)->RigJoints`. Define all 14 required joint names exactly in `rig_joints.v1`; root pelvis, neck, arm/leg pivots as reviewed canvas coordinates. Enforce finite coordinates, nonzero segment lengths and parent hierarchy. Joint and part data must share `reference_sha256`; no automatic pivot claim without evidence. User saves corrections as new immutable joint artifact. `RigProfile` uses 16 required semantic bone roles; optional extra controlled bones are explicitly included in 16..64 `runtime_bone_names`.

**P4.04 Spine export.** `atlas_builder.py: pack_regions(parts,max_width=2048,max_height=2048,padding=4)->Atlas`; deterministic area-desc and role-name tiebreak, no rotation in MVP, alpha pixel extrusion/padding (4px), single-page PNG RGBA8888; reject overflow with `RIG_ATLAS_OVERFLOW`. `spine_builder.py: build_spine_json(layout,joints,atlas)->SpineJSON` emits valid Spine 4.2 bones in parent-before-child order, slots/region attachments referring to exact names in atlas, valid rest positions. Recenter/transform geometry **once** from input image top-left y-down to rig local y-up. Do not write pseudo-Spine animations or keyframe `{angle}` for Spine4.2 rotation; if exported rotation animation keys exist they use official `value` semantics. No Genielabs source scripts or runtime import.

**P4.05 QA and approval.** `validation.py` verifies PNG SHA, atlas text/image, attachment references, all role-joint chains, matrix inverses, finite rest matrices, bone-name exactness, expression slot attachment names, 5 pose tests. Use official runtime browser loading in `src/features/rigging/PosePreview.tsx` or dedicated P4 test harness, before rig approval; P7 may later rehost it. Five poses: neutral, left/right reach, both knees flex, head turn. Crop and seam screenshots reviewed manually; human can explicitly approve/refuse. `RigManifest` refers to exact parts/layout/joints/profile/json/atlas and QA hashes. If visual QA not conducted mark `needs_review`; never issue `approved` from JSON-only test.

**P4.06 UI and routes.** `app/api/routes/rigging.py`, `app/repositories/rigs.py`, `src/features/rigging/{PartsGrid,SemanticMapper,JointCanvas,DepthOrderEditor,PosePreview,RigApproval}.tsx` implement create/segment/parts/position/layout/build/preview/approve routes from §12. JointCanvas converts screen clicks back to source pixel coordinates with scale/offset accounting, no physics world coordinates at this phase. Manual changes invalidate downstream rig version and P5+ compiled plans.

## Shared implementation invariants

- Windows 10/11 x64 local-first, Python 3.12, Node 22, 24 FPS, 1280x720, 48 kHz mono 16-bit PCM = 2000 samples per frame, 1–2 humanoid actors/shot, up to 3 props, <=30 shots, 24..720 frames/shot, world coordinates (x-right,y-up) in meters.
- ChannelDNA `channel_dna.v2`; `visual_style_hash` controls image/rig reuse; `performance_style_hash` controls Director/Motion; `narration_identity_hash` controls authoring/voice. No implicit conversion of creative prose into runtime actions.
- `rig_manifest.v1` is the final rig artifact; 16 required semantic roles, but approved runtime bones can be 16..64 by `rig_profile.runtime_bone_names` exactly. Any unexpected/missing bone is `RIG_BONE_SET_MISMATCH`.
- Rigged animation must be actual Spine 4.2 + compatible Spine-Pixi v8 / PixiJS 8.16+, using exact lockfile versions; not still-image Ken Burns and not Genielabs code. No hidden LLM APIs.
- IDs are backend-reserved; JSON/DB/OpenAPI/TS contract must stay synchronized. Use the error envelope `{"error":{"code":...,"message":...,"retryable":false,"details":{"path":...,"recovery":...}}}`; do not replace unsupported actions with idle.
