# P2 Genielabs real adapter

## Purpose

Genielabs `split_character.py` mixes image generation (Gemini) with OpenCV segmentation. This project calls **only** `segment_parts` on an atlas previously generated by G-Labs, so no Gemini SDK token is needed.

The runner uses pinned upstream script files, not a rewritten auto-rig engine. Get the upstream at a reviewed commit and keep it separate from our repo.

## Setup

```powershell
pip install -e ".[rig]"
git clone https://github.com/GenielabsOpenSource/spine-animation-ai.git vendor/spine-animation-ai
# Review/record the exact commit in the asset manifest.
```

## Workflow

1. Place G-Labs atlas at `character/parts_atlas.png` and the matching assembled reference at `character/reference.png`.
2. Segment: run the command below; inspect `parts/` and `debug/`. Raw Genielabs part names are `part_00`, `part_01`, etc, NOT semantic anatomy.
3. Write `semantic.json` mapping *all* detected part stems to anatomical labels (`torso`, `head`, `left_upper_arm`, `left_forearm`, ...).
4. Write `anchors.json` mapping every anatomical label to a verified absolute reference-image joint point `{x, y}`. Never fabricate missing joints.
5. After step 1 run `--from-stage 3` to use reviewed JSON; create Spine skeleton and atlas.

```powershell
python scripts/run_rig_pipeline.py --genielabs vendor/spine-animation-ai --atlas character/parts_atlas.png --reference character/reference.png --workspace character/rig --semantic character/semantic.json --anchors character/anchors.json --from-stage 1
# When the first pass raises because manual semantic/anchors are not yet ready:
python scripts/run_rig_pipeline.py --genielabs vendor/spine-animation-ai --atlas character/parts_atlas.png --reference character/reference.png --workspace character/rig --semantic character/semantic.json --anchors character/anchors.json --from-stage 3
```

`--from-stage 1` will segment, position and attempt building rig; it FAILS CLOSED when semantic/anchors are not present. It is safe to run only stage 1+2 by providing dummy absent semantics, then review. Use `--from-stage 3` after approvals.

Outputs `rig_config.json`, `skeleton.json`, `skeleton.atlas`, `skeleton.png`. Validate the resulting skeleton by loading it in the P0/P3 Spine runtime before marking asset ready.

## Known limitations

- Current rig configuration requires at least head and torso, and any limb present must have its parent part.
- Semantic mapping and pivot verification are **manual** for prototype quality; this is not one-click intelligent full-human rigging.
- P2 new-character *visual quality* remains to be reviewed with actual G-Labs generated assets.
